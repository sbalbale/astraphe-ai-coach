Introduction &
Platform Goals

APEX is a multi-source, AI-driven health and fitness coaching platform that processes physiological data from Apple HealthKit, Garmin Connect, and WHOOP, and converts it into personalized coaching intelligence via Google Gemini 2.5 Pro.

⚡
Scientific Rigor

All coaching recommendations are grounded in Training Stress Score (TSS), Chronic Training Load (CTL), Acute Training Load (ATL), and Training Stress Balance (TSB) — the gold standard frameworks for endurance performance management.

🧠
Contextual AI

APEX uses a RAG-enabled pipeline injecting real-time physiological context into Gemini 2.5 Pro via structured function calling, producing responses that are always grounded in the athlete's actual current data state.

📱
Native Mobile

Svelte 5 compiled to native via Capacitor, achieving sub-16ms frame times. Native HealthKit integration through Capacitor background runners ensures continuous, uninterrupted data fidelity.

🌍
Global Scale

Docker-containerized FastAPI on Cloud Run auto-scales to zero between requests, with Supabase PostgreSQL providing relational integrity and pgvector for long-term AI memory retrieval.

Audience. This document is written for engineers, product managers, and technical stakeholders involved in the development, deployment, or maintenance of the APEX platform. It assumes familiarity with REST APIs, containerization, and modern web development.

// Svelte 5 fine-grained reactivity via $state rune
export const trainingStore = createTrainingStore();

function createTrainingStore() {
  let ctl = $state(0);
  let atl = $state(0);
  let tsb = $derived(() => ctl - atl);          // auto-computed
  let hrv = $state({ current: 0, baseline: 0, trend: 0 });
  let readiness = $derived(() => computeReadiness(tsb, hrv));

  return {
    get ctl() { return ctl },
    get atl() { return atl },
    get tsb() { return tsb },
    get readiness() { return readiness },

    async sync() {
      const data = await apexApi.getAthleteMetrics();
      ctl = data.ctl;
      atl = data.atl;
      hrv = data.hrv;
    }
  };
}

Training
Algorithms

All performance management calculations are executed server-side using vectorized NumPy operations for computational efficiency. The canonical Banister PMC (Performance Management Chart) model governs the core load calculations.

Training Stress Score (TSS)

Quantifies the physiological demand of a workout, normalized against the athlete's threshold. For cycling, NP/FTP; for running, GAP and rGradeAdjPace are used.

Cycling TSS
TSS = (duration_sec × NP × IF) / (FTP × 3600) × 100
Where IF (Intensity Factor)
IF = NP / FTP
calculator.py — NumPy Implementation
import numpy as np

def compute_normalized_power(power_stream: np.ndarray) -> float:
    """30-second rolling average → 4th power mean"""
    rolling = np.convolve(power_stream,
                           np.ones(30) / 30,
                           mode='valid')
    return float(np.mean(rolling ** 4) ** 0.25)

def compute_tss(duration_s: int, np_watts: float,
                ftp: int) -> float:
    intensity_factor = np_watts / ftp
    return (duration_s * np_watts * intensity_factor) / (ftp * 3600) * 100
Chronic & Acute Training Load (CTL / ATL)

Exponentially weighted moving averages of daily TSS over 42-day (CTL) and 7-day (ATL) time constants. Computed fresh each day via a vectorized array scan over the athlete's full workout history.

CTL (Fitness) — τ = 42 days
CTL_n = CTL_{n-1} + (TSS_n - CTL_{n-1}) × (1 - e^(-1/42))
ATL (Fatigue) — τ = 7 days
ATL_n = ATL_{n-1} + (TSS_n - ATL_{n-1}) × (1 - e^(-1/7))
TSB (Form)
TSB_n = CTL_{n-1} - ATL_{n-1}
Vectorized CTL/ATL computation
def compute_pmc(tss_series: np.ndarray,
                 ctl_tau: int = 42,
                 atl_tau: int = 7) -> dict:
    n = len(tss_series)
    ctl = np.zeros(n)
    atl = np.zeros(n)

    k_ctl = 1 - np.exp(-1 / ctl_tau)
    k_atl = 1 - np.exp(-1 / atl_tau)

    for i in range(1, n):
        ctl[i] = ctl[i-1] + (tss_series[i] - ctl[i-1]) * k_ctl
        atl[i] = atl[i-1] + (tss_series[i] - atl[i-1]) * k_atl

    tsb = np.roll(ctl, 1) - np.roll(atl, 1)
    return {"ctl": ctl, "atl": atl, "tsb": tsb}
Readiness Score

A composite 0–100 score combining TSB, HRV deviation from baseline, resting HR, and sleep quality. Weights are configurable per athlete via profile settings.

Readiness — weighted composite
R = 0.35·(TSB_norm) + 0.30·(HRV_norm) + 0.20·(sleep_norm) + 0.15·(rHR_norm)

Each component is normalized 0–100 against a rolling 28-day baseline window. TSB is clamped to the range [-40, +40] before normalization.

AI Coach
— APEX

APEX is an autonomous AI coaching agent powered by Google Gemini 2.5 Pro. It operates via a physiological context injection pipeline — every conversation turn is prefixed with a machine-generated state snapshot of the athlete's current training and recovery status.

APEX Coaching Persona
Core Character
  • → Data-driven, evidence-based
  • → Concise (2–3 sentence responses)
  • → References specific metrics by name
  • → Motivating but scientifically honest
Personality Modes
Analytical Motivational Gentle Tough Love

Configurable per athlete in Profile settings. Injected as a system-level persona directive.

1
User sends message
The Svelte chat UI POSTs {message, conversation_id} to POST /api/v1/coach/chat. Connection is immediately upgraded to SSE for streaming.
2
Context injection
FastAPI fetches the athlete's current daily_metrics row and last 3 workouts from Supabase. This is serialized into a structured state block prepended to the Gemini system instruction.
3
RAG memory retrieval
The user's message is embedded via Gemini text-embedding and queried against coach_memory using pgvector cosine similarity. Top-3 retrieved memories are appended to the context.
4
Gemini 2.5 Pro inference
The enriched prompt is submitted to Gemini 2.5 Pro via the google-genai SDK with stream=True. Tokens are forwarded directly to the SSE response as they arrive.
5
Memory persistence
After response completion, the AI's reply is embedded and upserted into coach_memory, building the athlete's long-term coaching context over time.

Embedding Model

All text is embedded using models/text-embedding-004 (768 dimensions), Gemini's production embedding model. Embeddings are stored in pgvector's vector(768) column type.

Similarity query
embedding <=> query_vec ORDER BY LIMIT 3
What Gets Stored

rag/retriever.py
async def retrieve_context(
    athlete_id: str, query: str, top_k: int = 3
) -> str:
    # Embed the user's query
    result = await genai_client.aio.embed_content(
        model="models/text-embedding-004",
        content=query,
    )
    q_embedding = result.embedding

    # pgvector cosine similarity search
    rows = await supabase_client.rpc(
        "match_coach_memory",
        {
            "athlete_id": athlete_id,
            "query_embedding": q_embedding,
            "match_threshold": 0.75,
            "match_count": top_k,
        },
    ).execute()

    if not rows.data:
        return "No relevant coaching history found."

    return "\n".join([r["content"] for r in rows.data])

Security &
Compliance

Authentication
1
Supabase Auth (JWT)
All API routes validate Authorization: Bearer <jwt>. Row-level security policies ensure athletes can only access their own data.
2
OAuth 2.0 PKCE
Garmin and WHOOP tokens stored encrypted in Supabase vault. Refresh token rotation enforced. Never stored client-side.
3
Webhook HMAC Verification
All inbound webhooks from Garmin and WHOOP verify HMAC-SHA256 signatures before processing. Requests without valid signatures return 401.
Data Privacy
  • ◆ Data minimization. Only data required for coaching functionality is collected. Raw GPS streams are retained for 90 days then deleted.
  • ◆ Encryption at rest. All Supabase data encrypted with AES-256. Sensitive fields (tokens, HRV data) additionally encrypted at the application layer.
  • ◆ GDPR/CCPA. Full data export (GET /api/v1/athlete/me/export) and deletion (DELETE /api/v1/athlete/me) endpoints. Cascades to all related tables and vector memory.
  • ◆ HealthKit compliance. HealthKit data is never used for advertising. Usage strings are declared in Info.plist per Apple guidelines. Required for App Store approval.
Health Data Classification. HRV, heart rate, sleep, and HealthKit data are classified as sensitive health data under GDPR Article 9 and CCPA. A Data Processing Agreement (DPA) must be in place before storing this data in any third-party cloud service, including Supabase and Google Cloud.
