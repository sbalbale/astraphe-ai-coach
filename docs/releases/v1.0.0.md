# ASTRAPHE AI Coach — Release Notes (v1.0.0)

**Tag:** `v1.0.0`

## Overview

v1.0.0 is ASTRAPHE's **open source launch**. The project is now licensed under Apache-2.0, with a cleaned git history, contributor governance docs, and fixed setup/deployment documentation for anyone running their own instance. Alongside that, this release rolls up three months of product work since v0.4.0: a full rebrand from "Astrape" to "Astraphe," Garmin Connect and Intervals.icu integrations, an agentic AI coach with server-side tool calling and asynchronous chat, a migration from a single Proxmox Docker host to a 3-node k3s cluster, and CI/CD hardening that gates every production deploy on tests actually passing.

---

## Open Source Launch

- **License:** switched from a proprietary "all rights reserved" license to **Apache-2.0**.
- **Governance docs:** added `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant), `SECURITY.md` (vulnerability disclosure process), and a PR template.
- **Cleaned history:** removed committed database dumps, ad hoc debug scripts, and leaked credentials from the entire git history (not just the working tree) ahead of going public. See [SECURITY.md](https://github.com/sbalbale/astraphe-ai-coach/blob/main/SECURITY.md) for the disclosure process going forward.
- **Docs overhaul:** fixed a stale/incorrect repo structure and clone instructions in the README, split [`DEPLOYMENT.md`](https://github.com/sbalbale/astraphe-ai-coach/blob/main/docs/DEPLOYMENT.md) into "how the reference instance deploys" (private infra, for context) vs. an actual generic self-host guide, and corrected several docs that had drifted from the current k3s-based deploy.
- **Contributor CI:** every pull request — including from forks — now runs the backend `pytest` suite and mobile `vitest`/`svelte-check` automatically via `.github/workflows/deploy.yml`, with no secrets required.

## Rebrand: Astrape → Astraphe

The product was renamed from "Astrape" (and briefly "ArcStat") to **Astraphe** across the backend, mobile app, Supabase config/migrations, CI/infrastructure references, and documentation.

## New Integrations

### Garmin Connect (#15)
- Full Garmin Connect integration alongside existing Strava and WHOOP support.
- Fixed TSS/strain being understated by recording gaps, with a self-heal guard against silent failures.
- Sub-hourly polling support via `GARMIN_SYNC_POLL_MINUTES` for athletes who want faster sync.

### Intervals.icu (#9, #10)
- New wearable/training-log integration: ingests activity streams, heart rate, and sleep data from Intervals.icu.
- Deployed via Firebase Hosting REST API with idempotent retry handling.

---

## AI Coach: Agentic Tools & Async Chat

- **Server-side tool invocation** (#8): the coach agent can now call structured tools directly (workout data, memory read/write) rather than relying purely on prompt-based reasoning.
- **Asynchronous coach chat** (#17, #18): chat requests are submitted and the reply arrives when ready, instead of blocking on a long-running agentic call — with a fix for the coach silently faking success when a post-tool-call reply failed.
- Coach prompts clarified around data use and session metrics; Markdown response formatting normalized with new test coverage.

---

## Infrastructure: k3s Migration & CI/CD Hardening

- **Moved off a single Proxmox Docker host onto a 3-node k3s cluster**, reached via a Cloudflare Access SSH tunnel to a keepalived VIP. Deploys now use `kubectl set image` against a narrowly-scoped `ci-deployer` ServiceAccount; migrations run via `kubectl port-forward` to the cluster's Postgres pod.
- **Deploys are now gated on tests actually passing** (#24), not just branch-protection policy — `needs:` makes the dependency real regardless of how `main`'s HEAD got there.
- **PR builds** (#23): the backend Docker image now builds (but never publishes) on every pull request, catching build breaks before merge.
- **Test coverage enforcement** (#20): backend at 91%, mobile at 92%, both with an 80% CI gate.
- WHOOP token-refresh race condition fixed; startup backfill added for both Strava and WHOOP so a restarted backend catches up on anything missed while it was down.

## Upgrade Notes

1. **Review the new `LICENSE`** (Apache-2.0) if you maintain a fork or downstream deployment.
2. **Re-clone rather than pull** if you have an existing local clone — the git history was rewritten to remove committed secrets/data ahead of this release; a `pull` will attempt to merge in the old history.
3. **Apply all Supabase migrations** in order if upgrading an existing deployment.
4. **Garmin/Intervals.icu users:** register your own API credentials with each provider — see [SETUP.md](https://github.com/sbalbale/astraphe-ai-coach/blob/main/docs/SETUP.md).
