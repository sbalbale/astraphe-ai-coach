# ASTRAPE AI Coach — Release Notes (v0.4.0)

**Tag:** `v0.4.0`
**Base:** Builds on [v0.3.0](https://github.com/sbalbale/astrape-ai-coach/releases/tag/v0.3.0)
**Date:** May 28, 2026

---

## Overview

v0.4.0 is a major feature and infra release — setting the foundation for future rebranding and production scale. It completes the streaming data migration to Supabase Storage for workout fidelity, introduces structured editing/upserting for coach memories, upgrades the handling of athlete weight/height through full-stack, and lands major test, migration, and DX improvements across backend and mobile. If you run an Astrape deployment or mobile app, *update all packages and run all Supabase DB migrations before switching branches*.

---

## Highlights

### 🏃 **Activity Stream Storage Phase 2 (Supabase Storage Gzip Migration)**
- **Canonical source of workout activity streams** is now private gzip-compressed JSON in the `activity-streams` Supabase Storage bucket (`{athlete_id}/{workout_id}.json.gz`).
- **Combined API endpoint**: `GET /v1/activities/{workout_id}/detail` — delivers streams, laps, intervals, zones in a single request for lower latency and simplified frontend logic.
- **Redis-backed cache**: All heavy detail/stream payloads now cached by Redis (required in production, optional in dev).
- **Migration/backfill scripts:**
  - `scripts/migrate_streams_to_storage.py` — migrates legacy JSONB `time_series` rows to object storage.
  - Streaming reads/writes now dual-read Storage + DB until ready to drop the old JSONB column.
- **Docs**: See [`STREAM_STORAGE_MIGRATION.md`](https://github.com/sbalbale/astrape-ai-coach/blob/main/docs/STREAM_STORAGE_MIGRATION.md), [`PERFORMANCE.md`](https://github.com/sbalbale/astrape-ai-coach/blob/main/docs/PERFORMANCE.md).

### 🧠 **Coach Memory (Structured Entities, Edits, Deduplication Tools)**
- **Structured memory refs:** `coach_memories` table migration adds `memory_type`, `entity_key`, `event_date`, and `updated_at`.
- **API**: `list_memories`, `update_memory`, and `delete_memory` endpoints let users/coach update or upsert race events, notes, etc. (fully RAG and tooling aware).
- **Deduplicate endpoint/tools**: `/admin/coach-memories/merge-duplicates` prevents memory bloat from repeated athlete edits. See new scripts and service logic for migration/backfill tools.
- **Backfill embeddings**: `scripts/backfill_memory_embeddings.py` ensures all legacy rows have Gemini embeddings for accurate RAG.

### ⚡️ **Performance, Production & Deployment Improvements**
- **Redis in production** is now required on self-hosted (Proxmox) deployments — all shared API caching and rate limit state moves to Redis.
- **Docs**: Updated [`DEPLOYMENT.md`](https://github.com/sbalbale/astrape-ai-coach/blob/main/docs/DEPLOYMENT.md), [`REDIS.md`](https://github.com/sbalbale/astrape-ai-coach/blob/main/docs/REDIS.md).
- **Cloud Run legacy docs**: Documented as historical; all new prod rollout is Docker + GHCR + self-hosted Redis.
- **Backend tests**: Expanded, including RAG skip logic, storage helpers, and activity detail cache behavior.

### 🏋️ **Full-stack Athlete Weight/Height Tracking**
- **DB migration** adds `weight_kg` and `height_cm` to `biometrics` for time-series body tracking.
- **WHOOP and Garmin ingest**: Now parses and upserts both historical and webhook payloads to both profile and biometrics tables. Sync is robust to changed or missing fields.
- **Mobile**: Profile and analysis surfaces now always show latest known weight with support for fallback/merge logic from biometrics or athlete profile.

## Upgrade Notes

1. **Apply all Supabase migrations in order.** (See migrations above — breaking for streams, memory/entity features, and body metrics.)
2. **Backfill if migrating**: Run `backend/scripts/migrate_streams_to_storage.py` and `backend/scripts/backfill_memory_embeddings.py` if you have legacy workout or memory data.
3. **Verify Redis connectivity**: `REDIS_URL` must be set and reachable for full performance and production safety.
4. **Mobile update**: Optional but recommended for unified workout detail, correct body metrics, and swim activity unit handling.
