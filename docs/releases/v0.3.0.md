# ASTRAPE AI Coach — Release Notes (v0.3.0)

**Tag:** `v0.3.0`  
**Base:** Builds on [v0.2.0](https://github.com/sbalbale/astrape-ai-coach/releases/tag/v0.2.0)

## Overview

v0.3.0 is the largest release to date — 100 commits across 10 days (May 17–27, 2026). It ships a production-grade CI/CD pipeline, full Progressive Web App (PWA) support, a significantly smarter AI coach with long-term memory and cleaner response formatting, deep WHOOP integration hardening, push notifications for iOS/Android/web, comprehensive rate limiting, a major database performance overhaul, and a wide array of bug fixes.

---

## New Features

### CI/CD Pipeline (GitHub Actions)

- Full GitHub Actions deploy workflow (`.github/workflows/deploy.yml`) that builds the Docker backend image, pushes to GHCR, deploys to Proxmox via Cloudflare Access SSH tunnel, and runs Supabase migrations — all triggered on push to `main`
- Firebase Hosting CI workflows added (`firebase-hosting-merge.yml`, `firebase-hosting-pull-request.yml`) for the mobile PWA
- Supabase email templates (confirm, recovery, invite) deployed automatically as part of the CI pipeline
- `APP_VERSION` included in the `/health` endpoint response for deployment verification
- Cloud Build updated to `us-east4` region with Cloud Logging enabled

### Progressive Web App (PWA)

- Full PWA support added to the SvelteKit mobile app: service worker (`service-worker.ts`), web app manifest, and a complete set of PWA icons (192×192, 512×512, maskable)
- iOS-specific PWA behavior fixed: routing issues when launched from the iOS home screen are resolved
- SvelteKit configured with the static adapter for correct SPA behavior
- Client-side navigation module (`lib/nav.ts`) added to handle PWA and Capacitor routing uniformly
- Auth session handling overhauled for PWA context: `getSession` timeout added, `replaceState` used on OAuth callback to prevent reload loops, auth store fully rewritten with resilient session refresh
- LAN IP origins added to the CORS allowlist to support mobile-device PWA testing against a local backend

### AI Coach — Long-Term Memory & Cleaner Responses

- **Long-term memory**: The coach stores and retrieves athlete-specific memories via pgvector embeddings in a new `coach_memories` table, with configurable similarity threshold and automatic retry on embedding write failures
- **Document parsing**: The coach can ingest attached documents (PDF, plain text) and parse their content into memory for future retrieval
- **Internal reasoning stripped**: Coach responses are filtered to remove `<scratchpad>`, model thinking artifacts, and internal XML markup before delivery — only the final `<response>` content reaches the athlete
- **`<response>` XML parsing**: Reliable extraction of `<response>...</response>` blocks ensures structured Gemini outputs arrive cleanly regardless of surrounding text
- **Weekday awareness**: The coach now knows the current day of the week and can provide day-relative training advice (e.g. "it's Wednesday — you have two days before your long run")
- **Model upgrade**: Switched from `gemma-4-31b-it` to `gemma-4-26b-a4b-it` for an improved reasoning-to-speed ratio
- **Emoji guidance tightened**: Prompt rules updated to prevent emoji overuse in coach responses
- **Context deduplication**: Improved deduplication of context regeneration to avoid redundant Gemini API calls when the underlying data has not changed

### Push Notifications (iOS, Android, Web)

- Full push notification system implemented using VAPID keys for web push and FCM for native platforms
- `push_tokens` database table added with row-level security to store device tokens per athlete
- Notification infrastructure documented in `docs/PUSH_NOTIFICATIONS.md`
- VAPID key configuration added to `.env.example`

### Rate Limiting & Security Hardening

- **IP rate limiting**: Middleware added to rate-limit requests per IP address at the FastAPI layer
- **Redis-backed rate limiting**: Configurable Redis integration for distributed rate limiting; falls back gracefully to in-memory when Redis is unavailable; Upstash Redis supported for serverless deployments
- **WHOOP HMAC verification**: Webhook signature verification fully implemented and enforced with a dedicated test suite validating the HMAC logic
- **Security advisor fixes**: Applied all Supabase security advisor recommendations — RLS policy cleanup, index optimization, privilege cleanup (removed over-broad REVOKE on `rls_auto_enable`), and authenticated role grants restored
- **Strain sanitization**: Explicit input sanitization and policy enforcement for strain data added with dedicated test coverage
- **Backend hardening**: `/docs` and `/redoc` endpoints restricted to `APP_ENV=development`; debug routes return 404 in production

### Workout PATCH Endpoint

- `PATCH /v1/workouts/{id}` added, allowing partial updates to existing workout records (sport type corrections, TSS overrides, notes, etc.)

### Athlete-Local Timezone Handling

- New `time_utils.py` module providing date/time utilities that normalize all relative references to the athlete's `timezone_offset_min`
- All relative date references in coach context ("today", "yesterday", weekday names) now resolve in the athlete's local timezone rather than server UTC
- Greeting utility on the frontend updated to use athlete-local time for morning/afternoon/evening messages

## Improvements

### Training Physiology Algorithms

- **Readiness score**: Now blends TSB (Training Stress Balance) with the existing recovery composite for a more physiologically grounded readiness signal
- **Strain score**: Replaced linear scaling with an exponential saturation curve, better modeling the non-linear relationship between training load and cardiovascular strain
- **PMC recalculation ordering**: Fixed an ordering bug where PMC was recalculated before the latest workout's TSS was fully committed, causing the tail-day value to lag by one step
- **TSS recalculation threading**: Expensive TSS recalculation operations moved to thread pools to avoid blocking the async event loop on large history backlogs
- **Recovery computation guard**: Guard added to skip recovery computation when required biometric inputs are absent, preventing NaN propagation into downstream scores

### Performance & Caching

- **In-memory caching**: Athlete profile and dashboard data are now cached in-memory with background refresh to reduce repeated Supabase round trips
- **Workout detail caching**: Individual workout detail responses are cached; GZip compression enabled at the FastAPI middleware layer
- **Analysis cache improvements**: Cache key fingerprinting improved to reduce unnecessary regeneration; strain refresh path made resilient to transient Supabase failures
- **DB operations in threads**: Long-running database operations (TSS recalculation, history aggregation) now run in thread executors to keep the async event loop responsive

### WHOOP Integration

- **Biometrics-only backfill**: New `reprocess_whoop_biometrics` endpoint to backfill only biometric (recovery/sleep) data without requiring full workout reprocessing — useful after HR zone changes
- **Proactive token refresh**: Background loop checks WHOOP OAuth token expiry and refreshes proactively before expiry, eliminating mid-day auth failures
- **JSON OAuth URL support**: OAuth credential flow refactored to support JSON-encoded credential URLs, simplifying cross-environment configuration
- **Secret stripping**: WHOOP service no longer logs raw OAuth credentials in any code path

### Database Optimization

- **Missing indexes**: Added composite `btree` indexes on `athlete_id + date DESC` patterns for `workouts`, `biometrics`, `tss_history`, and related tables, eliminating full-table scan patterns identified by the security advisor
- **RLS policy performance**: Rewrote RLS policies to avoid `initplan` (per-row sub-selects) by using the `(SELECT auth.uid())` pattern for plan-level evaluation — significant improvement on tables with many rows
- **Duplicate indexes dropped**: Removed redundant ascending index on `workouts` shadowed by the DESC composite index; ran `ANALYZE` to update query planner statistics
- **PGRST002 retry handling**: Backend retries on PostgREST schema cache miss (PGRST002) with 6-second total exponential backoff; mobile frontend retries on 503 responses — eliminating transient errors after schema migrations
- **Supabase health probe**: New `supabase_health.py` module; `/health` endpoint now performs a lightweight Supabase connectivity probe
- **DB connection timeouts**: Explicit statement timeout and connection timeout configured on the Supabase client to prevent indefinite hangs

### Logging & Observability

- Replaced all `print()` statements in backend hot paths with structured Python `logging` calls
- Uvicorn log configuration enabled for JSON-formatted structured logs in production
- Cloud Build updated to use Cloud Logging for centralized log aggregation on GCP

### Mobile / Frontend

- Switched from `@iconify-icon/svelte` to `@lucide/svelte` for a lighter, tree-shakeable icon set
- Readiness score card now opens an explanatory modal when tapped
- Profile connections page: Apple HealthKit and Garmin integrations show "Coming Soon" placeholders instead of broken states
- Lap bar chart updated to CSS grid layout for pixel-perfect alignment; x-axis tick rendering refined
- Touch scrubbing on workout stream charts restricted to chart rows only (was leaking to surrounding page elements)
- Map and GPS trace touch UX improved; pre-loading added for workout detail map tiles
- Default coach behavior changed: opens a new chat session by default instead of loading the most recent conversation

## Bug Fixes

| Bug | Fix |
|-----|-----|
| Greeting displayed wrong time of day in non-UTC timezones | Uses athlete-local time via `timezone_offset_min` |
| PostgREST PGRST002 schema cache miss returned spurious 401 errors | Retry with exponential backoff on backend and 503 retry on frontend |
| PMC tail-day rest decay not applied when no workout existed for today | Fixed PMC recalculation ordering |
| Raw WHOOP OAuth credentials appeared in structured log output | Secret stripped from all log call sites |
| iOS PWA: deep links navigated to a blank page | Fixed SPA routing and `svelte.config.js` adapter config |
| OAuth callback caused repeated full-page reloads in PWA/Safari | Use `replaceState` instead of `href` assignment on callback |
| Chart touch scrubbing intercepted by iOS scroll container | Restricted pointer events to chart row elements |
| Strain NaN propagated into readiness when HR zone data was missing | Guard added before strain computation |
| Coach sent emoji-heavy responses despite tone guidelines | Prompt rules tightened with explicit emoji guidance |
| New chat loaded last conversation instead of empty state | Default changed to always open a fresh session |

## Upgrade Notes

1. **Run all 12 new Supabase migrations** before deploying the updated backend.
2. **Redis (optional)**: Set `REDIS_URL` in backend `.env` to enable distributed rate limiting; the app falls back to in-memory without it.
3. **VAPID keys**: Generate and set `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` in the backend `.env` to enable web push notifications.
4. **WHOOP webhook secret**: Ensure `WHOOP_WEBHOOK_SECRET` is configured — webhook requests are now validated with HMAC-SHA256 and will return 403 without it.
5. **New user tier**: New accounts now default to `premium` via the `20260525141000` migration; review if this does not match your intended onboarding flow.
6. **Mobile package manager**: Continue using **pnpm** in `mobile/` (unchanged from v0.2.0).
